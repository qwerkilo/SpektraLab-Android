# SpektraLab for Android

Unofficial Android port of the SpektraLab film/paper simulation engine (Vulkan). RAW in, physically modelled film + paper out, on device.

Java UI + JNI over an **out-of-tree C++ engine**. No Gradle, no Kotlin build, no automated tests.

## Build: Termux, hardcoded paths

There is no `gradlew`. Scripts assume the repo is at `$HOME/SpektraLab-apk`, the engine at `$HOME/SpektraLab-android-adreno/engine`, Termux prefix `/data/data/com.termux/files/usr`, SDK 36, NDK `28.2.13676358`.

Engine source: upstream `JamesQiu2005/SpektraLab` at `445e314`, then `git apply patches/engine-android.patch`.

Run in this order:

```bash
bash app/build/build-libs-raw.sh        # once; downloads LibRaw 0.22.2, adds HE/HE* sniff
bash app/build/build-engine.sh          # all engine TUs; pass names to rebuild a subset
bash app/build/build-native.sh          # both JNI units; links libspektrafilm_engine.so
bash app/build/build-libs.sh            # stages .so and rewrites DT_NEEDED
bash app/build/build-dex.sh             # javac + d8; regenerates app/build/sources.txt
python3 app/build/gen-stock-catalog.py  # only when profiles changed
bash build-apk.sh                       # aapt + zip + sign + check-libs; copies to /sdcard/Download
```

Never hand-copy `libspektrafilm_engine.so` into `app/build/apk/lib` (README still shows this). `build-libs.sh` renames `libjpeg.so.8` / `libz.so.1` to `libjpeg_8.so` / `libz_1.so` and rewrites every DT_NEEDED; skipping it ships a library that cannot load (E-9000). `check-libs.py` fails `build-apk.sh` if the closure is broken.

`build-apk.sh` signs with `$HOME/SpektraLab-apk/debug.keystore` (gitignored). `app/build/apk/res` and most of `app/build/apk/assets` are local-only staging: no script creates them. `app/src/main/assets` is gitignored too (~30 MB of profiles and resources).

On Windows without Termux, `app/build/build-apk-windows.ps1` compiles, dexes with the R8 jar, reuses a base APK's assets and native libraries, then align-signs. Set `SPK_KEYSTORE`, `SPK_KS_PASS`, `SPK_KEY_PASS`, `SPK_KEY_ALIAS`; pass `-BaseApk` only when the newest `*-console.apk` is not the donor.

## Gradle / Material 3

`./gradlew assembleDebug` is the primary build for the M3 migration. It uses the installed JDK 17 via `gradle.properties`, compiles against SDK 34, and stages `assets/` plus `arm64-v8a` libraries from `app/build/SpektraLab-1.3.4-qa.apk` (override with `-PbaseApk=<path>`). Set the same `SPK_*` variables to sign with the release key; without them Gradle uses its debug key and the APK will not update an installed release build. For Android 15/16 devices with 16 KB pages, run `./gradlew align16k` (needs build-tools 36) and install `app/build/outputs/apk/debug/app-debug-16k-signed.apk`; the plain debug APK is only 4 KB zip-aligned. The legacy scripts remain the fallback for the pre-M3 tree.

## Upstreams

- **Engine**: `JamesQiu2005/SpektraLab`, branch `assist/vulkan-engine-1.3.4` at `445e314`. The engine is out of tree; sync by reapplying `patches/engine-android.patch` to the new baseline, never by merging the desktop app.
- **Android app**: `SAINTTaiYi/SpektraLab-Android`, branch `master`. Fetch it as a second remote and merge fixes into the feature branch. The fork's `origin` is `qwerkilo/SpektraLab-Android`; pushing there does not update the user-facing channel.
- On Windows, build-tools 34 `d8` crashes on `MainActivity$1.class` (`NullPointerException`). Use the R8 jar in `android-sdk/cmdline-tools/latest/lib/r8.jar` with JDK 17 instead.

## Where the code lives

- `MainActivity.java` — ~4.7k lines, programmatic `View` UI in one file. No XML layouts; theme only in `app/build/values/themes.xml`.
- `SpektraLabEngine.java` — JNI facade. `prepare(libDir)` loads bundled `.so` by absolute path before the engine; there is intentionally no `static {}` loader, so a load failure keeps its cause. One native result buffer, serialized by `RENDER_LOCK`.
- `spektralab_jni.cpp` — session, render, JPEG/TIFF/DNG export. `spektralab_raw_jni.cpp` — LibRaw decode.
- The engine itself is not in this repo; only `patches/engine-android.patch` and `docs/tiling.md` are.

## Traps

- `spk_result.row_stride_px` is in **pixels**, 4 uint16 per pixel: index `rgba16 + y * stride * 4`.
- Dispatches are capped at 65,535 workgroups × 256 threads; the engine chunks with a push-constant base. Per-plane binding range (`maxStorageBufferRange`) is still the hard import wall — `DeviceProbe` derives the cap and canary-tests it. `HARD_PIXEL_CAP` 42 MP, `IMPORT_LONG_EDGE` 8000. README's 4700 is stale.
- `build-engine.sh <unit>...` is incremental, but a header change forces a full rebuild (vtable/ABI skew). Keep that stamp.
- Both JNI units are recompiled every time on purpose; a stale `spektralab_raw_jni.o` links fine and breaks the first RAW open.
- `app/build/sources.txt` is generated by `build-dex.sh`; don't edit it.
- Reversal/slide film is allowed: `scan_film` must ride the stock delta, not the slider delta. The Print stock stays stored for a later negative but is unused while a slide is selected; preview and export must send the same value.
- `[E-xxxx]` codes in `SpkError.java` are user-facing: E-1001 binding range, E-1108 HE/HE*, E-9000 native load, E-2001/2002 update. Keep the number when changing the text.

- Version is duplicated in `AndroidManifest.xml` (`versionCode` + `versionName`) and `update.json`.
- `CF_TOKEN=... ./scripts/announce.sh <code> <name> <apk|-> "note"...` rewrites/commits/pushes `update.json`, purges jsDelivr, uploads the APK to KV (24 MiB limit), and creates a GitHub Release.
- **Identity split**: `announce.sh`, `UpdateCheck`, and README target `SAINTTaiYi/SpektraLab-Android`; this checkout's `origin` is `qwerkilo/SpektraLab-Android`. Pushing here does not update the channel users read. Confirm the target before announcing.

## Verify

No Gradle test suite. Pure JVM checks live in `app/src/test/java/app/spektralab/*Check.java` (Palette, M3Tokens, ThemeMode, SpectrumSamples, SpectrumCurve, OpticsDelta, GateScale, ScanSample, ConsoleLayout, FilmBrand, SafeFileName, ReleaseUrl, SpkError). Run them with `./gradlew checkJvm`; it compiles the checks against the app's real debug classpath and runs each one from the repository root, so `M3TokenCheck` can read `res/values/colors.xml` and `themes.xml`. They do not need a device. Plain `javac -cp android.jar` no longer compiles the main sources because `MainActivity` imports AppCompat and Material; the legacy Termux scripts are the pre-M3 fallback and do not build this tree. `python app/build/check-manifest.py` pins permissions, exports, cleartext, and backup; `python app/build/test-gen-stock-catalog.py` covers the profile generator. Then `adb install -r`, and watch logcat tags `SpektraLabJNI` and `SpektraLabRAW`. On the device, `DebugSink` POSTs diagnostics to `127.0.0.1:8770` (Termux-side sink). Driver telemetry goes to `report.workshop.skin`. Manual device matrix: `docs/testing/manual-device-checklist.md`.

When the Termux engine toolchain is unavailable, a device build can replace `classes.dex` inside the shipped APK and re-sign it; the native libraries and assets stay from that APK. Do not hand-copy `libspektrafilm_engine.so`.

## Pre-commit hook

Enable once per clone: `git config core.hooksPath .githooks`.
The hook syntax-checks staged `.sh` files with `bash -n`, staged `.py` files with `ast.parse`, rejects staged text that is not valid UTF-8, and runs `git diff --cached --check`.
It does not run the Android build.

## Git workflow

Never commit directly to `master`. Create a feature branch, verify the change, then merge into `master`.
